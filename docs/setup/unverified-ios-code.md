# iOS code not compiled on the build host

Status: **not compiled here**. The development Mac has Swift 6.1.2, the macOS 15.5 SDK, no Xcode and no iOS SDK.
Everything below has only been checked by reading Apple's documentation symbol JSON
(`developer.apple.com/tutorials/data/documentation/...`) on 2026-11-13, plus host type-checks of
the language patterns used (stand-in types; same language mode 5 and strict concurrency).
Scope: `ios/Packages` except `ZoroApp`.

Confidence levels:
- **confirmed in documentation**: every Apple symbol, its signature, async/throws and availability match the docs.
- **partly confirmed**: the symbols are confirmed, but some behaviour or concurrency detail can only be shown by a real build or a device.
- **unconfirmed**: the docs did not settle it.

## Fixed in this audit

| File | Problem | Fix |
|---|---|---|
| `ZoroKit/Sources/ModelRouter/iOS/FoundationModelsIntentAssist.swift` | Passed String *variables* inside `@InstructionsBuilder` / `@PromptBuilder` closures. The docs list only `buildExpression(Instructions)` and `buildExpression(Prompt)`, so this form is not documented and may not type-check. | Changed to `LanguageModelSession(instructions: String)` and `session.respond(to: text, generating:)`, which are the forms in Apple's own samples. |
| `ZoroDevice/Sources/NativeActionBroker/iOS/HomeKitSceneRunner.swift` | `MainActor.assumeIsolated` in `homeManagerDidUpdateHomes(_:)`. HomeKit does not document which queue it uses for delegate calls, so the app would trap if a call ever arrived off the main thread. | Switched to `Task { @MainActor in … }` (the pattern type-checks on the host). |
| `ZoroDevice/Sources/NativeActionBroker/iOS/AlarmKitScheduler.swift` | Apple's AlarmKit article says: "AlarmKit expects a widget extension if an app supports a countdown presentation." Timers use one, but `ZoroAlarmMetadata` was `internal`, so the widget extension could not declare `ActivityConfiguration(for: AlarmAttributes<ZoroAlarmMetadata>.self)`. | Made `ZoroAlarmMetadata` `public` with `public init()`. |
| `ZoroDevice/Sources/NativeActionBroker/iOS/UIApplicationURLOpener.swift` | A nonisolated async method read the main-actor `UIApplication.shared` and passed a non-Sendable options dictionary across actors, which gives strict-concurrency warnings. | Marked `open(_:)` `@MainActor`. This isolated async witness satisfies the nonisolated `URLOpening` requirement (the pattern type-checks on the host). |

### Fixed in this audit

| File | Problem | Fix |
|---|---|---|
| `ios/ZORO/ZOROApp.swift` | The Live Activity was requested on `scenePhase == .background`. ActivityKit documents `ActivityAuthorizationError.visibility`: "The app tried to start the Live Activity while it was in the background", so it would never have started. | The request now happens on the `.active → .inactive` transition, while the app is still in the foreground. The photo-index task is still scheduled on `.background`. |
| `ios/ZOROWidgets/ZoroAlarmCountdownActivity.swift` | `Text(timerInterval: Date.now...countdown.fireDate)` traps at run time once `fireDate` is in the past, because a `ClosedRange` with lower > upper is a precondition failure. | The upper bound is clamped with `max(now, fireDate)`. |
| `ios/ZOROWidgets/ZOROWidgetsBundle.swift` | The control runs `StartVoiceIntent` from the ZoroAppUI package, but the extension did not declare an `AppIntentsPackage`. The `AppIntentsPackage` docs say a target that uses another module's intents declares its own package that includes that module's package. | Added `ZOROWidgetsAppIntents: AppIntentsPackage` that includes `ZoroAppIntentsPackage`. |
| `ios/Packages/ZoroApp/Sources/ZoroAppUI/iOS/SetupCodeScanner.swift` | `startScanning()` was called inside `makeUIViewController`, before the scanner's view is in a window. The error was swallowed by `try?`, so the scanner could stay idle. | Scanning now starts in `updateUIViewController`, guarded by `isScanning` (`@MainActor var isScanning: Bool`, confirmed). |
| `ios/ZOROTests/ZOROAppTests.swift` | Used XCTest, which breaks the "Swift Testing only" rule in CLAUDE.md. | Rewritten with `import Testing` (`@Test`, `#expect`, `#require`).
